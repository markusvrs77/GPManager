# Kafka Manager, этап 3: управление топиками

**Дата:** 2026-08-31
**Направление:** Data Flow → Kafka
**Статус:** утверждено, готово к планированию
**Предыдущие этапы:** `2026-08-31-kafka-manager-stage1-design.md`,
`2026-08-31-kafka-manager-stage2-design.md`

## Цель

Создание и удаление топиков, изменение их конфигурации и увеличение числа
партиций — прямо на вкладке «Обзор кластера», где список топиков уже есть.

## Условия

Прежние: кластер PLAINTEXT, десятки топиков, опасные операции разрешены с
подтверждением и записью в журнал, автообновления нет.

## Выбранный подход

Действия встраиваются в существующий «Обзор кластера»: кнопка «+ Топик» в
шапке карточки топиков, а в развороте топика — «Конфигурация», «Добавить
партиции», «Удалить».

Отвергнуто:

- **отдельная вкладка «Топики»** — список топиков уже есть в обзоре, и
  второй такой же экран означал бы два места, где одно и то же показано
  по-разному, плюс пятый пункт в меню Kafka;
- **модалка поверх обзора** — у топика десятки изменяемых конфигов, им
  нужно место, а модалка на пол-экрана хуже раскрывающейся панели.

## Что умеет библиотека

Сверено по исходникам `kafka-python` 3.0.11.

| Метод / класс | Контракт |
|---------------|----------|
| `NewTopic(name, num_partitions=-1, replication_factor=-1, replica_assignments=None, topic_configs=None)` | описание нового топика |
| `create_topics(new_topics, timeout_ms=None, validate_only=False, ...)` | создание |
| `delete_topics(topics, timeout_ms=None, raise_errors=True)` | удаление |
| `NewPartitions(total_count, new_assignments=None)` | **итоговое** число партиций, не приращение |
| `create_partitions({topic: NewPartitions(n)})` | увеличение числа партиций |
| `describe_configs(config_resources, include_synonyms=False, config_filter='modified')` | `{resource_type: {resource_name: {config_key: {данные}}}}` |
| `alter_configs(config_resources, ...)` | у ресурса `configs` — `{key: value}` либо `{key: (op, value)}` |
| `ConfigResource(resource_type, name, configs=None)`, `ConfigResourceType.TOPIC` | адресация ресурса |

Две детали, на которых легко ошибиться:

1. `config_filter` по умолчанию `'modified'` — вернутся только ключи с
   не-дефолтными значениями. Для экрана редактирования нужен `'dynamic'`:
   все ключи, которые можно менять, вместе с текущими значениями.
2. `NewPartitions` принимает **итоговое** количество партиций. Передать
   «сколько добавить» — значит попросить у брокера меньше, чем есть, и
   получить ошибку.

## Данные

Новых таблиц нет. Действия пишутся в `kafka_audit`, заведённую на этапе 1
и используемую с этапа 2.

Конфиги топиков **не** попадают в срез `kafka_snapshots`: их десятки на
топик, они меняются независимо от метаданных, и держать их в срезе значило
бы показывать устаревшее. Конфигурация грузится по требованию — при
открытии панели у конкретного топика.

После любого изменения (создание, удаление, партиции, конфиги) срез обзора
пересобирается: топик создан или удалён, а на экране прежний список —
прямой путь к недоразумению.

## Модули

### `modules/kafka_topics.py`

Чистые функции, тестируются без брокера:

- `validate_topic_name(name) -> str` — возвращает очищенное имя либо
  поднимает `ValueError` с человеческим текстом. Правила Kafka: непустое,
  не длиннее 249, только `a-zA-Z0-9._-`, не `.` и не `..`.
- `build_topic_spec(data) -> dict` — из формы в
  `{"name", "partitions", "replication", "configs"}`; партиций и реплик не
  меньше 1, пустые конфиги отбрасываются, retention переводится из часов в
  миллисекунды.
- `parse_configs(described, topic) -> list[dict]` — ответ `describe_configs`
  в плоский список `{"key", "value", "source", "default", "sensitive",
  "read_only"}`, отсортированный по имени ключа.
- `build_config_changes(current, wanted) -> dict` — только реально
  изменившиеся ключи; если ничего не поменялось, пустой словарь.
- `assert_can_grow(current_count, target_count) -> None` — поднимает
  `ValueError`, если целевое число партиций не больше текущего.

### `modules/kafka_client.py`

Добавляются, оставаясь единственным местом с `import kafka`:

- `create_topic(cluster, spec)`;
- `delete_topic(cluster, name)`;
- `add_partitions(cluster, name, total_count)`;
- `fetch_topic_configs(cluster, name) -> dict` — сырой ответ
  `describe_configs` с `config_filter='dynamic'`;
- `alter_topic_configs(cluster, name, changes)`.

Ошибка брокера про запрет удаления переводится в «Брокер запрещает
удаление топиков: включите delete.topic.enable». Ошибка «топик уже
существует» — в «Топик <имя> уже есть в кластере».

### `kafka_routes.py`

| Метод | Путь | Назначение |
|-------|------|-----------|
| POST | `/api/kafka/clusters/<id>/topics` | создать топик |
| DELETE | `/api/kafka/clusters/<id>/topics/<name>` | удалить топик |
| POST | `/api/kafka/clusters/<id>/topics/<name>/partitions` | увеличить число партиций |
| GET | `/api/kafka/clusters/<id>/topics/<name>/configs` | конфигурация топика |
| PUT | `/api/kafka/clusters/<id>/topics/<name>/configs` | изменить конфигурацию |

Коды: 200 — успех, 400 — плохой ввод, 404 — кластер не найден, 409 —
топик уже существует или партиций не больше текущего, 502 — кластер
недоступен.

Текущее число партиций для проверки роста берётся из среза обзора: он уже
загружен и содержит `partitions` по каждому топику.

## Экран

Правки в `templates/kafka.html` и `static/js/kafka.js` — новых файлов нет.

Шапка карточки «Топики» получает кнопку **«+ Топик»**; она раскрывает
форму: имя, партиций, фактор репликации, retention (в часах, с пометкой
«пусто — по умолчанию брокера») и cleanup.policy (`delete` / `compact`).

В развороте топика появляются три кнопки:

- **Конфигурация** — раскрывает таблицу ключей: имя, текущее значение,
  пометка «по умолчанию» для тех, что не переопределены. Значения
  правятся на месте; кнопка «Сохранить» отправляет только изменившиеся.
- **Добавить партиции** — поле с итоговым числом, подставлено текущее + 1.
  Рядом предупреждение: увеличение меняет распределение по ключам, записи
  с тем же ключом после изменения пойдут в другую партицию.
- **Удалить** — подтверждение вводом имени топика.

## Опасные действия

Удаление топика и увеличение партиций необратимы. Оба требуют
подтверждения через `gpConfirm`; удаление — с вводом имени.

Уменьшить число партиций Kafka не позволяет, поэтому проверка делается до
запроса: если введено число не больше текущего, ответ 409 с текстом
«У топика уже 6 партиций, уменьшить нельзя — только увеличить».

Каждое из четырёх действий пишется в `kafka_audit` с намерением и
результатом.

## Ошибки

| Ситуация | Поведение |
|----------|-----------|
| Библиотеки нет | Кнопки действий заблокированы, баннер с командой установки. |
| Кластер недоступен | 502, красный баннер, срез на экране остаётся. |
| Топик уже существует | 409 с именем топика. |
| Брокер запрещает удаление | 502 с подсказкой про `delete.topic.enable`. |
| Партиций не больше текущего | 409, до обращения к брокеру. |
| Конфиги не изменились | 200 и сообщение «Изменений нет» — запрос к брокеру не отправляется. |

## Тесты

1. `validate_topic_name`: пустое, пробел, `.`, `..`, 250 символов,
   кириллица, двоеточие — все отвергаются с внятным текстом; обычное имя
   и имя с точкой и дефисом проходят.
2. `build_topic_spec`: партиции и реплики по умолчанию, отбрасывание
   пустых конфигов, приведение retention из часов в миллисекунды.
3. `parse_configs`: разбор ответа `describe_configs` с пометкой
   «по умолчанию», сортировка, скрытие значения у `sensitive`.
4. `build_config_changes`: только изменившиеся ключи; пустой результат,
   когда всё совпадает.
5. `assert_can_grow`: равное и меньшее число отвергаются, большее
   проходит.
6. `modules/kafka_client`: `add_partitions` передаёт **итоговое** число;
   ошибка «уже существует» и запрет удаления переводятся в человеческий
   текст.
7. Роуты через `flask.test_client`: создание пишет в журнал, удаление
   пишет в журнал, 409 на уменьшении партиций, 200 и «изменений нет» при
   пустом наборе изменений, 502 при недоступном кластере.
