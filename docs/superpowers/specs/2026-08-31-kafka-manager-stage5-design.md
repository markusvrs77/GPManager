# Kafka Manager, этап 5: управление доступами (ACL)

**Дата:** 2026-08-31
**Направление:** Data Flow → Kafka
**Статус:** утверждено, готово к планированию
**Предыдущие этапы:** спеки этапов 1–4 в этой же папке.

## Цель

Вкладка «Доступы»: увидеть правила ACL кластера, выдать права и отозвать
их — с превью того, что именно будет удалено.

## Условия и важная оговорка

Кластер заказчика работает по PLAINTEXT, состояние authorizer на брокерах
неизвестно. Поэтому вкладка начинается не со списка, а с диагностики.

ACL без аутентификации не защищают: если на брокерах не задан
`authorizer.class.name`, любой запрос вернёт `SecurityDisabledError`; если
authorizer включён, но клиенты ходят по PLAINTEXT без SASL, все они для
Kafka — один `User:ANONYMOUS`, и различить их правами нельзя. Инструмент
обязан говорить это прямо, а не показывать пустой список.

## Три состояния экрана

1. **Авторизация выключена** — брокер ответил `SecurityDisabledError`.
   Показываем объяснение и что дописать в `server.properties`
   (`authorizer.class.name` — `StandardAuthorizer` для KRaft либо
   `AclAuthorizer` для ZooKeeper), плюс напоминание про перезапуск
   брокеров.
2. **Авторизация включена, подключение PLAINTEXT** — список правил
   работает, но сверху предупреждение: клиенты неразличимы, все
   `ANONYMOUS`; полноценное разграничение начинается с SASL.
3. **Авторизация включена, подключение SASL** — обычный режим.

Состояние определяется по факту ответа брокера и по `security_protocol`
подключения, а не спрашивается у пользователя.

## Что умеет библиотека

Сверено по `kafka-python` 3.0.11:

| Метод | Контракт |
|-------|----------|
| `describe_acls(acl_filter)` | **кортеж** `(список ACL, KafkaError)` — не просто список |
| `create_acls(acls)` | список объектов `ACL` |
| `delete_acls(acl_filters)` | список `ACLFilter`; удаляет всё, что подошло |
| `ACL(principal, host, operation, permission_type, resource_pattern)` | правило |
| `ACLFilter(...)` | те же поля, допускают `ANY` |
| `ResourcePattern(resource_type, resource_name, pattern_type=LITERAL)` | ресурс |
| `ResourcePatternFilter(resource_type, resource_name, pattern_type)` | фильтр ресурса |

Перечисления: `ACLOperation` (ALL, READ, WRITE, CREATE, DELETE, ALTER,
DESCRIBE, DESCRIBE_CONFIGS, ALTER_CONFIGS, CLUSTER_ACTION,
IDEMPOTENT_WRITE, ANY), `ACLPermissionType` (ALLOW, DENY, ANY),
`ResourceType` (TOPIC, GROUP, CLUSTER, TRANSACTIONAL_ID,
DELEGATION_TOKEN, USER, ANY), `ACLResourcePatternType` (LITERAL,
PREFIXED, MATCH, ANY). Все — числовые, с атрибутом `.name`.

## Данные

Новых таблиц нет. Правила **не кэшируются**: устаревший список прав
опаснее лишнего запроса — увидеть правило, которого уже нет, хуже, чем
подождать секунду. Чтение по кнопке, как везде.

Выдача и отзыв пишутся в `kafka_audit`.

## Модули

### `modules/kafka_acl.py`

Чистые функции и справочники:

- `OPERATIONS`, `RESOURCE_TYPES`, `PATTERN_TYPES`, `PERMISSIONS` — списки
  допустимых значений с русскими подписями для интерфейса.
- `validate_principal(text) -> str` — приводит к виду `User:имя`; голое
  имя дополняется префиксом `User:`, пустое отвергается.
- `build_acl_spec(data) -> dict` — форма в
  `{"principal", "host", "resource_type", "resource_name",
  "pattern_type", "operations": [...], "permission"}`; операции
  проверяются по справочнику, `host` по умолчанию `*`.
- `build_filter_spec(data) -> dict` — то же для фильтра, но с допустимым
  `ANY` в каждом поле.
- `expand_preset(name, data) -> list[dict]` — шаблон в набор
  спецификаций. Шаблоны: `reader` (READ и DESCRIBE на топик, READ на
  группу), `writer` (WRITE и DESCRIBE на топик), `full` (ALL на топик).
- `format_acl(acl) -> dict` — объект библиотеки в плоский словарь со
  строковыми именами перечислений.

### `modules/kafka_client.py`

- `AclsDisabled(KafkaUnavailable)` — отдельная ошибка, чтобы роут отличал
  «авторизация не включена» от «кластер недоступен»;
- `fetch_acls(cluster, filter_spec) -> list` — сырые объекты правил;
  распаковывает кортеж и поднимает `AclsDisabled` при
  `SecurityDisabledError`;
- `create_acls(cluster, specs) -> int` — число созданных правил;
- `delete_acls(cluster, filter_spec) -> int` — число удалённых.

### `kafka_routes.py`

| Метод | Путь | Назначение |
|-------|------|-----------|
| GET | `/kafka/acl` | страница |
| POST | `/api/kafka/clusters/<id>/acls/list` | правила по фильтру; он же превью удаления |
| POST | `/api/kafka/clusters/<id>/acls` | выдать права |
| POST | `/api/kafka/clusters/<id>/acls/delete` | отозвать по фильтру |

Коды: 200 — успех, 400 — плохой ввод, 404 — кластер не найден, 409 —
авторизация на брокерах не включена, 502 — кластер недоступен.

409 выбран намеренно: это не ошибка запроса и не отказ кластера, а
несовместимое состояние — на брокерах нет authorizer.

## Экран

`templates/kafka_acl.html` + `static/js/kafka_acl.js`, пятый пункт меню.

Сверху — карточка состояния: включена ли авторизация, каким протоколом
подключены, сколько правил найдено. Ниже фильтр (принципал, тип ресурса,
имя) и список правил: принципал, ресурс, операция, разрешение, хост.

Форма выдачи: принципал, тип ресурса, имя, тип паттерна, операции
(множественный выбор), ALLOW/DENY, хост. Три кнопки-шаблона заполняют
форму, но **не отправляют** её — видно, что именно будет создано.

Отзыв: та же форма используется как фильтр. Сначала «Показать, что
попадёт» — список под удаление, потом подтверждение с числом правил.
Если под фильтр попадает принципал, под которым подключён сам Opsentri,
в подтверждении отдельная строка: так можно отрезать себе доступ.

## Ошибки

| Ситуация | Поведение |
|----------|-----------|
| Библиотеки нет | Кнопки заблокированы, баннер с командой установки. |
| Авторизация не включена | 409 и экран-объяснение вместо пустого списка. |
| Кластер недоступен | 502, красный баннер. |
| Принципал пуст | 400 «Укажите принципал, например User:svc_etl». |
| Ни одной операции | 400 «Выберите хотя бы одну операцию». |
| Фильтр удаления никого не нашёл | 200 и «Под фильтр ничего не попало» — удаление не выполняется. |

## Тесты

1. `validate_principal`: голое имя дополняется до `User:имя`; пустое и
   пробелы отвергаются; `Group:x` сохраняется как есть.
2. `build_acl_spec`: значения по умолчанию (`host="*"`,
   `pattern_type="LITERAL"`, `permission="ALLOW"`), отказ на неизвестной
   операции и пустом списке операций.
3. `expand_preset`: `reader` даёт правило на топик и правило на группу;
   `writer` — только на топик; неизвестный шаблон отвергается.
4. `format_acl`: перечисления превращаются в строки.
5. `modules/kafka_client.fetch_acls`: распаковка кортежа;
   `SecurityDisabledError` превращается в `AclsDisabled`.
6. Роуты: список, создание с записью в журнал, 409 при выключенной
   авторизации, превью удаления, удаление с записью в журнал, 400 на
   пустом принципале.
