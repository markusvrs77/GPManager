# Kafka Manager, этап 4: просмотр и отправка сообщений

**Дата:** 2026-08-31
**Направление:** Data Flow → Kafka
**Статус:** утверждено, готово к планированию
**Предыдущие этапы:** спеки этапов 1, 2 и 3 в этой же папке.

## Цель

Вкладка «Сообщения»: заглянуть в топик — последние записи, записи с
оффсета или с даты — и отправить сообщение вручную.

## Условия

Прежние: PLAINTEXT, десятки топиков, опасные операции с подтверждением и
журналом, автообновления нет.

## Выбранный подход

Отдельная вкладка, четвёртый пункт в разделе Kafka.

Отвергнуто:

- **встроить в «Обзор кластера»** — у просмотра свой экран: выбор режима
  чтения, партиции, лимита, раскрытие тела записи. Обзор и так вместил
  управление топиками;
- **читать через консьюмер-группу** — см. ниже, это меняло бы чужие
  оффсеты.

## Ключевое решение: читаем без группы

Чтение идёт через `assign` + `seek`, **без `group_id` и без коммитов**.

Если читать как консьюмер-группа, просмотр сдвигал бы закоммиченные
оффсеты: заглянул в топик — и боевой потребитель пропустил сообщения.
Инструмент наблюдения не должен менять то, за чем наблюдает.

`modules/kafka_client.open_consumer` уже создаёт консьюмера без группы и
с `enable_auto_commit=False` — этап 1 заложил это верно.

## Что умеет библиотека

Сверено по `kafka-python` 3.0.11:

| Метод | Контракт |
|-------|----------|
| `consumer.partitions_for_topic(topic)` | множество номеров партиций |
| `consumer.assign(partitions)` | ручное назначение, без группы |
| `consumer.seek(partition, offset)` | позиция чтения |
| `consumer.poll(timeout_ms=0, max_records=None)` | `{TopicPartition: [ConsumerRecord]}` |
| `consumer.offsets_for_times({tp: ms})` | оффсет по времени |
| `producer.send(topic, value=None, key=None, headers=None, partition=None, timestamp_ms=None)` | future |
| `producer.flush(timeout=None)` | дождаться отправки |

`ConsumerRecord`: `topic`, `partition`, `offset`, `timestamp`,
`timestamp_type`, `key`, `value`, `headers`, `serialized_value_size`.

`key` и `value` — байты либо `None`.

## Данные

Новых таблиц нет, и сообщения **не** кэшируются: они меняются каждую
секунду, срез показывал бы вчерашнее. Каждое открытие — живой запрос, но
только по явной кнопке.

Отправка пишется в `kafka_audit`: топик, размер значения, первые символы
и оффсет, который вернул брокер. Тело сообщения целиком в журнал не
пишется — оно может быть большим и содержать данные клиентов.

## Модули

### `modules/kafka_messages.py`

Чистые функции:

- `decode_payload(raw) -> dict` — байты в
  `{"kind": "empty|text|json|binary", "text": str|None, "size": int,
  "hex": str|None, "truncated": bool}`.
  Порядок: пусто → `empty`; UTF-8 разобрался и это валидный JSON → `json`
  с отступами; просто UTF-8 → `text`; иначе → `binary` с размером и
  первыми 64 байтами в hex. Avro и Protobuf не угадываем: честное «не
  текст» лучше мусора на экране.
- `trim_text(text, limit=8192) -> (str, bool)` — обрезка для показа.
- `build_read_plan(data) -> dict` — форма в
  `{"topic", "partition", "mode", "limit", "offset", "timestamp_ms"}`;
  режимы `latest`, `offset`, `timestamp`; лимит зажат в 1..500; для
  `offset` требуется неотрицательное число, для `timestamp` — разбираемая
  дата.
- `format_record(record) -> dict` — сырая запись (`dict` с байтами) в
  JSON-безопасную: `offset`, `partition`, `timestamp` строкой
  `YYYY-MM-DD HH:MM:SS`, `key` и `value` — результаты `decode_payload`,
  `headers` — список пар со строковыми значениями.

### `modules/kafka_client.py`

- `read_messages(cluster, topic, plan) -> list[dict]` — назначает
  партиции, встаёт на нужную позицию, читает, возвращает **сырые**
  записи (байты внутри). Декодированием занимается `kafka_messages`.
- `send_message(cluster, topic, key, value, partition=None) -> dict` —
  `{"partition": int, "offset": int}` из ответа брокера.

Границу держим прежнюю: `TopicPartition` и `ConsumerRecord` наружу не
выходят, наружу — словари.

### `kafka_routes.py`

| Метод | Путь | Назначение |
|-------|------|-----------|
| GET | `/kafka/messages` | страница |
| POST | `/api/kafka/clusters/<id>/messages/read` | прочитать записи |
| POST | `/api/kafka/clusters/<id>/messages` | отправить сообщение |

Чтение — POST, а не GET: у запроса пять параметров, включая дату, и
прятать их в query-строку неудобно; плюс это подчёркивает, что каждый
вызов реально идёт в кластер.

Коды: 200 — успех, 400 — плохой ввод, 404 — кластер не найден, 502 —
кластер недоступен.

## Экран

`templates/kafka_messages.html` + `static/js/kafka_messages.js`.

Шапка: выбор кластера, выбор топика (из среза обзора — он уже есть),
режим (последние / с оффсета / с даты), поле лимита, партиция (все или
номер), кнопка «Прочитать».

Список записей: партиция, оффсет, время, ключ, начало значения. Строка
раскрывается — полное значение в `<pre>`, заголовки, размер. Для
двоичных — размер и hex-превью вместо текста.

Фильтр по подстроке работает **по загруженным записям**, а не по топику:
Kafka не умеет искать по содержимому, и делать вид, что умеет, нельзя.
Подпись под полем говорит об этом прямо.

Отправка — раскрывающаяся форма: ключ, значение, партиция. Подтверждение
показывает топик и начало значения. После отправки — тост с партицией и
оффсетом.

## Ошибки

| Ситуация | Поведение |
|----------|-----------|
| Библиотеки нет | Кнопки заблокированы, баннер с командой установки. |
| Кластер недоступен | 502, красный баннер. |
| Топик не выбран | 400 «Выберите топик». |
| Оффсет за концом партиции | Пустой результат и подсказка «Записей нет: возможно, оффсет за концом партиции». |
| Дата позже последней записи | Пустой результат и та же подсказка. |
| Чтение ничего не вернуло за таймаут | Пустой результат и «Не дождались записей». |

## Тесты

1. `decode_payload`: пустое, текст, JSON (форматируется), не-UTF-8
   (размер и hex), очень длинный текст.
2. `trim_text`: короткое не трогает, длинное режет и ставит флаг.
3. `build_read_plan`: три режима; лимит зажимается; отрицательный оффсет
   и неразбираемая дата отвергаются; топик обязателен.
4. `format_record`: время в строку, ключ `None` даёт `empty`, заголовки
   в список пар.
5. `modules/kafka_client.read_messages`: на подменённом консьюмере —
   правильные `assign`/`seek` для каждого режима, соблюдение лимита.
6. Роуты: чтение возвращает отформатированные записи, отправка пишет в
   журнал с оффсетом, недоступный кластер даёт 502.
