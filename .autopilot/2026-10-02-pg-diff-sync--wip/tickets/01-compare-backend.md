## Что должно заработать

`POST /api/pg/compare/start` запускает фоновую задачу `pg_compare`. Ей передают источник, приёмник, а также схемы целиком и/или отдельные таблицы. По каждой таблице задача выясняет:
- сколько строк в источнике и в приёмнике;
- сколько строк добавить, изменить и удалить — по ключу, а у таблиц без ключа по мультимножеству;
- статус: `same | differs | no_dest | no_source | structure_diff | duplicate_keys | error | cancelled`;
- какой ключ найден и откуда он взят.

Результаты пишутся в SQLite `pg_compare_results` по мере готовности. Их отдают:
- `GET /api/pg/compare/results?job_id=`;
- `GET /api/pg/compare/latest?source_connection_id=&dest_connection_id=`.

Источник только читается. Стоп через существующий `/api/jobs/<id>/stop` отменяет активный запрос, задача получает `cancelled`.

Здесь же появляется `modules/pg_sync_common.py` с примитивами для таска 02: `open_pg`, `table_columns`, `row_hash_sql`, `stream_copy`, `StopWatch`. Сигнатуры описаны в `interfaces.md`. Если сигнатуру приходится менять, это записывается в «Построено тасками».

## Критерии приёмки

- [ ] `open_pg`:
  - не-postgres подключение отклоняется с понятной ошибкой;
  - источник открывается read-only;
  - обе сессии нормализуются: DateStyle, IntervalStyle, TimeZone, extra_float_digits, bytea_output.
- [ ] `expand_selection`:
  - схема раскрывается в r/p-таблицы обеих сторон; таблица, которая есть только в приёмнике, получает `no_source`;
  - отдельные таблицы сверяются с каталогом; если таблицы нет в приёмнике — `no_dest`;
  - листья партиций выбранного родителя исключаются;
  - дубли схлопываются;
  - неизвестные имена отклоняются.
- [ ] `compare_table` с ключом:
  - `COPY (SELECT key::text…, md5(ROW(cols sorted)::text)) TO STDOUT` пишется во временную таблицу сессии приёмника;
  - по ней считаются `to_insert` / `to_update` / `to_delete`;
  - дубликаты ключа в источнике дают `duplicate_keys`.
- [ ] `compare_table` без ключа и при расхождении структуры:
  - без ключа сравнение идёт через EXCEPT ALL по хешам;
  - если наборы колонок разные — `structure_diff`, данные при этом не читаются.
- [ ] Ключ берётся по цепочке PK → уникальный индекс → `sync_keys`, через существующие функции `table_catalog`. Ключ должен быть в обеих таблицах.
- [ ] Раннер:
  - на каждую таблицу заводится item, результат пишется сразу после таблицы;
  - ошибка в таблице даёт ей `error`, остальные таблицы продолжаются;
  - по стопу — `conn.cancel()`, задача `cancelled`, оставшиеся items `skipped`.
- [ ] Маршруты:
  - валидация (оба подключения postgres, src≠dst, выбор не пуст), иначе 400 с текстом по-русски;
  - POLICY: start — `sync.run`, results и latest — `sync.view`;
  - в config есть `source_connection_id` и `dest_connection_id`.
- [ ] Тесты: SQL-построители, раннер на фейках, маршруты. Весь `python -m pytest -q` зелёный.
