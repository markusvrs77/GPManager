# Отчёт: Postgres — сравнение двух баз и загрузка только разницы

## Готово

Во вкладке **Postgres Toolkit → «Синхронизация»** появился второй режим — **«Сравнение и разница»**. По умолчанию открывается прежний «Перенос», он не изменился. Страница Greenplum тоже не изменилась.

Что умеет новый режим:

- **Сравнить две базы PostgreSQL.**
  - Источник и приёмник берутся из шапки страницы.
  - Можно отметить схему целиком, отдельные таблицы или и то и другое вместе.
  - По каждой таблице видно статус (совпадает / отличается / нет в приёмнике / нет в источнике / структура отличается), число строк с обеих сторон и сколько строк будет добавлено, изменено и удалено.
  - Результаты появляются по мере сравнения, последнее сравнение сохраняется.
  - Источник только читается.
- **Загрузить только разницу.**
  - Новые строки вставляются, изменённые обновляются, совпадающие не трогаются.
  - Ключ определяется сам: первичный ключ → уникальный индекс → сохранённый ключ. Таблица без ключа догружается недостающими копиями строк.
  - Каждая таблица применяется одной транзакцией: либо целиком, либо никак.
- **Удалить лишние строки** — только по отдельной галке, по умолчанию она выключена.
- **Полная загрузка (TRUNCATE + INSERT)** — для любой таблицы вместо разницы. Есть и отдельной кнопкой, без сравнения.
- **Создать и залить** — для таблицы, которой нет в приёмнике, по отдельной галке. Таблица создаётся с первичным ключом и теми же типами.
- **Стоп и история.**
  - «Стоп» отменяет текущий запрос и откатывает текущую таблицу.
  - Задачи видны в ленте «Запуски» как «Сравнение баз» и «Загрузка разницы».
  - После загрузки показано «ожидалось / сделано», и это сохраняется после перезагрузки страницы.

**Как проверено.**

- Независимая проверка подняла приложение на живом PostgreSQL 17 с двумя базами. Подтвердилось:
  - числа сравнения совпали с реальностью;
  - разница, удаление по галке и полная загрузка дали верный результат в приёмнике;
  - источник не изменился: контрольные суммы до и после совпали.
- Найденный на этой проверке дефект «создать и залить» исправлен и перепроверен там же.
- Тесты: 683 прошли, до работы было 552.

**Запустить:**
```
pip install -r requirements.txt -r requirements-dev.txt
python app.py
```
Затем: Postgres Toolkit → «Синхронизация» → «Сравнение и разница».

## Что не вошло

| Что | Почему |
|---|---|
| Передача по сети только отличающихся строк | Приёмник меняется только на разницу, но источник целиком копируется во временную таблицу приёмника. Выборка «только разница» прямо из источника требует временных объектов на проде — отложено как отдельная оптимизация |
| Сравнение/загрузка по расписанию | В задаче не было; расписания есть в «Перенос» |
| Автоисправление расхождений структуры | Для этого есть существующая «Проверить DDL». Таблицы с другой структурой помечаются и не грузятся |
| Сравнение вьюх, функций, последовательностей | Задача про данные таблиц |

## Открытые вопросы и известные ограничения

**Создание таблицы**
- Переносятся типы, NOT NULL, collation и первичный ключ. Default-ы, CHECK/FK и прочие индексы не переносятся.
- Если таблица использует тип или функцию, которых нет в приёмнике (например, свой enum), создание этой таблицы завершится ошибкой. Данные при этом не страдают.
- Партиционированный родитель создаётся в приёмнике обычной таблицей, с пометкой в итоге.

**Загрузка**
- Колонка identity ALWAYS вне ключа не обновляется, поэтому фактическое «изменено» может быть меньше ожидаемого.
- После загрузки последовательности serial/identity в приёмнике продвигаются вперёд. В редком случае последовательность может сдвинуться назад, но дубля это не даёт.
- Полная загрузка без сравнения может дважды залить лист партиции, если его корень в другой схеме. Это лишняя работа, данные не портятся.

**Окружение**
- Автопоиск ключа по уникальному индексу требует PostgreSQL 11+. На PG 10 такая таблица получит ошибку сравнения.
- Временная таблица (staging) — в схеме `opsentri_sync_stage` приёмника, нужно право CREATE в приёмнике.
- Несколько установок Opsentri на один приёмник не поддерживаются.

**Что проверено не до конца**
- Перерисовка при опросе и восстановление «ожидалось» проверены вне браузера, на фейковом DOM. В настоящем браузере не открывались.
- Есть небольшое дублирование вспомогательного кода между новыми модулями. На работу не влияет.
