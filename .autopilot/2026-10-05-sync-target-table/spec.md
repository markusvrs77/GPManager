# Спецификация: загрузка в другую таблицу приёмника

## Задача (слова пользователя)

> «еще добавь в синхронизацию возможность в другую таблицу грузить, тоесть если таргет таблица не выбрано то в основную грузить нужно»

Ответы на брифинге:
- где: «Greenplum + Postgres»;
- если цели нет в приёмнике: «Создать по структуре источника».

## Контракт

### Поле `targets`

Во всех маршрутах запуска и в конфиге задачи появляется необязательное поле:

```json
"targets": {"src_schema.src_table": "dst_schema.dst_table", ...}
```

- **Ключ** — имя таблицы источника, как оно выбрано (`schema.table`).
- **Значение** — `schema.table` или просто `table`; во втором случае схема берётся из источника. После нормализации всегда хранится `schema.table`.
- **Пустое значение**, отсутствие ключа или отсутствие поля — грузим в одноимённую таблицу, как сейчас. Без `targets` поведение и команды байт-в-байт прежние.
- **Цель, совпадающая с источником**, после нормализации выбрасывается из карты.

### Проверка (маршрут, до создания задачи; ошибка — 400 с понятным текстом)

- Каждая часть имени цели соответствует `^[a-z_][a-z0-9_$]{0,62}$`. Регистр не меняем — просто не принимаем заглавные. Пробелы, кавычки, запятые и лишние точки запрещены.
- Ключ должен быть среди выбранных таблиц задачи.
- Две таблицы источника не могут грузиться в одну цель.
- Цель не может совпадать с одноимённой целью другой выбранной таблицы. Пример: выбраны `a.x` → `a.y` и `a.y` без карты — конфликт.
- «Партиции целиком» (`/api/gpcopy/partition-diff/start`) с непустыми `targets` — 400 «Для режима партиций загрузка в другую таблицу не поддерживается».

Общий модуль `modules/sync_targets.py`:
- `normalize_targets(raw, selected) -> dict` — бросает `ValueError`;
- `target_of(targets, schema, table) -> (dst_schema, dst_table)` — возвращает `(schema, table)`, если карты нет.

Все бэкенды пользуются только им.

### Нет цели в приёмнике — создать по структуре источника

- **Создаётся только цель из карты.** Перед загрузкой раннер проверяет, существует ли цель, и если нет — создаёт её по структуре источника: колонки, типы, NOT NULL; для Greenplum — то же распределение (`DISTRIBUTED BY` / `RANDOMLY`). В остальном действует прежнее поведение.
- **Если не вышло создать** — ошибка таблицы, без загрузки.
- **Только приёмник.** DDL выполняется только на приёмнике; источник только читается.
- **Подготовка приёмника** (precheck / create-missing / add-columns на странице) тоже учитывает `targets`: сравнивает источник с целью и создаёт цель под новым именем, а не одноимённую.

### Режимы

| Режим | Что сделать |
|---|---|
| GP «Полная замена» (`/api/gpcopy/start`, gpcopy) | Таблицы с картой идут через `--include-table-json` с `dest` (или иным способом, поддерживаемым `build_gpcopy_command`). `--truncate` / `--drop` / `--append` действуют на цель. |
| GP «Окно с очисткой» (`/api/gpcopy/start-date`) | Уже понимает `dest` в `table_configs`: маршрут заполняет его из `targets`. Очистка окна идёт по цели. Для таблицы с картой не раскладывать по листовым партициям; цель — корень. |
| GP «По ключу» (`/api/gpcopy/sync/apply`) | Уже понимает `target` в `table_configs`: заполнить из `targets` и проверить. Таблицы без ключа, ушедшие в полную / по датам, тоже получают карту. |
| GP «watermark» (`/api/gpcopy/increment/start`) | `dest` в include-JSON и чтение отметки из цели. |
| PG «Перенос» (copy_pipe, toolkit=pg) | `ensure_dest_table` и `copy_table_pipe` — по цели. COPY с явным списком колонок. |
| PG «Сравнение» (`/api/pg/compare/start`) | Сравнивается источник с целью. В результатах есть поле `target` (`schema.table` или null). В Excel — колонка «Приёмник». |
| PG «Загрузка разницы» (`/api/pg/diff-load/start`) | Карта берётся из задачи сравнения (`compare_job_id`). Если в запросе пришли `targets`, отличные от сравнения, — 400. `action: create` создаёт цель. |

### Прогресс

Строки задачи (job_items) по-прежнему хранят имя источника. Если gpcopy пишет в логе имя приёмника, атрибуция прогресса должна узнавать и его, чтобы таблица с картой корректно становилась `done`.

### Интерфейс

- **Блок «Куда грузить»** рядом с выбором таблиц: список выбранных таблиц со строкой «в таблицу» (placeholder — то же имя), прокрутка и фильтр, счётчик переназначенных. Ввод приводится к нижнему регистру, ошибки формата видны сразу.
- **Хранение** — `state.targets` в localStorage рядом с выбором.
- **Отправка** — `targets` уходит во все вызовы запуска и расписания, в fallback-задачи и в подготовку приёмника.
- **«Партиции целиком»** — блок недоступен, с объяснением.
- **Сводка перед запуском** — «N таблиц в другие таблицы».
- **Вкладка Postgres** — перенос и сравнение получают тот же блок; в результатах сравнения видно «→ цель».

## Безопасность

- Идентификаторы — только через `sql.Identifier` / `quote_ident`; значения — параметрами.
- Источник не меняется никогда.
- DELETE — по-прежнему только с явным флагом (`delete_missing` / `window_cleanup`).
